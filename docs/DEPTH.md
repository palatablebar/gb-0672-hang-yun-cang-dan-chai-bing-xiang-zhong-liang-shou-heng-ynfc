## 对账规则

原始逻辑输入=采纳行+隔离行+空行+重复表头+同值重复。业务计算按 DATA-DICTIONARY.md 分别核验，不能把上级与下级重复加总。所有隔离保留编号、原值、原始行号和稳定原因码。

## 航次质量对照规则

跨规则版本复核时，历史原因码按版本化字典（`app/dictionary.py`，字典版本随清单持久化）显式映射：

| 归类方式 | 触发条件 | 当前归类 |
|---|---|---|
| CURRENT | 现行规则直接产生 | 原码即现行码 |
| DIRECT | 旧码一对一对应，且新旧证据在同节点同时成立 | 改写为现行码 |
| SPLIT | 旧码一对多（E101/E201/E401），历史证据足以唯一定位 | 按证据拆分到现行码 |
| RETAINED | 字典无对应（E999）或证据不足以区分 | 记 UNMAPPED，保留历史原码 |

不变量：历史原码永不改写、记录永不丢失、无映射不静默改名且继续阻断待人工处理。拆并（MISSING_PARENT/DEPENDENCY_CYCLE）与重量（WEIGHT_MISMATCH）结论按现行复核重新判定为 BLOCKING/RESOLVED/MANUAL_REVIEW。清单按 `(run_id,dict_version)` 唯一落库，同一规则版本重跑批号不变、不新增对照；构建在内存完成后才写库，失败回退库内旧版并返回 warning。跨航次对照以（主单·节点·历史原码）为稳定键折叠，下载入口 `GET /api/runs/{run_id}/checklist/download` 与 `GET /api/voyage/compare/download`。
